# Lessons from solved problems

Rules for writing code, each learned from a real bug. Check new code and reviews against them. When a fix teaches something new, add or sharpen a rule here (one line or two, plus the commit that taught it); skip fixes that teach nothing reusable.

## Identity and ownership

- **Contexts other than membership key data by `MemberID`, never `IdentityID`.** The identity provider's ID only finds or creates the member. Using it elsewhere shreds a key that does not exist on account deletion and hides a member's own notifications. A member principal in tests carries both IDs, like the real middleware. (4e609a7 privacy, notify; d411f3d safety.)
- **A reference names its owner.** When a stored reference can point into different contexts, store its kind per owning context (`member`, `external` trusted contact, `staff` shift), so a later lookup asks the right owner. (6bdb935: a duty shift resolved as a trusted contact.)
- **A record created lazily starts with optional fields.** A field required in the contract must exist from the first response; a member created on first sign-in has no name yet. (f90019c)
- **A record created lazily is deleted as a tombstone, not a delete.** Otherwise the next request of the same identity (a session still valid, or replayed after the identity was deleted) creates it again under a new ID. Keep the key column and a deletion marker, and refuse it on lookup. (account deletion: `membership.members.deleted_at`.)
- **Authorize before the lookup.** A service method that loads a row by ID and only then checks the caller's role answers 404 for unknown IDs and 401/403 for known ones, so anyone can probe which IDs exist. Check that the caller may use the operation at all first, then load, then check the row-specific rule (kind, author). (knowledge: create draft, update, submit, publish, reject; chat: room moderation)

## Transactions and delivery

- **Side effects after commit go through a timer or the outbox created in the same transaction.** A push sent after commit is lost if the process dies in between. (dc3bffd)
- **A consumer must not depend on a third service to accept an event.** Look external data (a phone from the identity provider) up when it is needed, outside database transactions; otherwise an outage exhausts redeliveries and loses the event. (b668657)
- **A provider error text never comes straight from `net/http`.** `*url.Error` repeats the request URL, and the APNs URL holds the device token, so a logged transport error leaks it. Unwrap `*url.Error`, keep only the status and the provider's reason code, and test that the error text (not only the log) lacks the token, phone and credentials. (notify providers)
- **A secret never travels in an event or a timer.** The outbox, the event stream and the consumer's tables keep the payload, so a one-time link or sign-in code in it is a secret at rest in three places. Mint it at send time (plan links) or hand it over with a synchronous call that persists nothing (sign-in codes: `notify.SendSignInCode`), and let the caller own retries. (plan links; courier hook)
- **Anything that counts or remembers "used once" must be shared before a second replica.** In-memory rate limits multiply by the replica count, and an in-memory PoW replay store accepts a solution once per replica; the worker's SMS guards multiply the daily budget the same way. Keep them in `platform/ratelimit` with the PostgreSQL store, and test with two handlers on one database. (multi-replica)
- **Rate limits on a shared resource need their own counters per traffic class.** One SMS guard for sign-in codes and critical SMS would let anyone who can request codes to a member's number use up the per-number limit and daily budget her crisis SMS needs. Same limits, separate counters. (courier hook)
- **A "not erased" check and the erasure take one lock.** Under READ COMMITTED an `INSERT ... WHERE NOT EXISTS (erased)` can pass before a concurrent erasure commits, and the erasure's `DELETE` cannot see the uncommitted insert: both commit and a deleted member's row stays forever. Both transactions take `pg_advisory_xact_lock` on the same key (the pseudonym) before the check and before the delete; a multi-key transaction takes its locks in a fixed order. Rows that carry no member (a closing, a rating) need their own erased marker (the object's pseudonym), or they arrive late and slip past. (analytics: `LockPseudonym`, `erased_subjects`)
- **Idempotency needs a natural key.** One pending verification request or one open escalation per member is a partial unique index; `ON CONFLICT (id)` with a fresh id makes nothing idempotent. (cbd1339)

## Safety and privacy

- **Check an image's declared size before decoding it.** `image.DecodeConfig` reads only the header; refuse width×height above a limit before `image.Decode`, or a small file that claims a huge image exhausts memory. (sharing photo processing review)
- **Never drop a critical notification silently.** A budget or guard that blocks a crisis SMS fails loudly (`failed`, Error log with an event name for alerting), and the daily budget does not apply to critical messages. (dc3bffd)
- **A critical message never waits for an optional part.** A `{link}` text whose link could not be made was skipped (or retried), which for the SOS SMS to an external contact would mean no alert at all; a critical SMS goes out at once with its text without the link (`<template>.no_link`), and the mint has a short timeout. Anything added to a crisis message later (links, names, personalisation) gets the same fallback.
- **A log line never joins a person to health data.** Log a record ID (check-in, escalation), not the member ID next to a flag, score or category. (6e7ee83)
- **Bind ciphertexts and wrapped keys to their owner.** Associated data names the field and the row (`<context>.<table>.<column>|<id>`); a wrapped data key is bound to its member and KEK, so a copied value fails to open. (c0b8e37)
- **A restriction on a member never closes her crisis path.** Suspension, blocks or limits stop her reaching others; the help request, her SOS, the emergency plan and her own-data routes stay open, with an e2e test. (moderation review: suspension first answered 403 on every route.)
- **Documentation claims only what the mechanism guarantees.** Crypto-shredding does not reach backups until they expire. (cc56a71)

- **Tests connect as the application role, not a superuser.** The e2e database URL uses `birge_app`, so a schema missing from `db/roles.sql` fails a test instead of production; `db.TestRolesCoverEverySchema` checks every `CREATE SCHEMA` has a grant. (all context schemas but two had no grants.)

- **A browser client on the Kratos API flow needs `Origin` stripped at the gateway.** Kratos answers 400 "the request was made as part of an AJAX request" to any API flow with an `Origin` header; the native apps send none, so only the web build failed ("Could not sign in"). The auth gateway drops it, as it drops `Cookie`. Test sign-in in a browser, not only on a device. (web demo)

- **A held chat message is not a crisis unless it says so.** The chat client showed the red crisis banner with Help for every held message, and a newcomer's "hello" (held for review, reason `newcomer`) looked like an emergency. Only a crisis hold carries `crisisPhones`; any other hold is a calm review notice. (chat)

## Contracts and code generation

- **Quote YAML strings that contain punctuation in flow style.** A comma inside `{description: ...}` split it into an extra field and invalidated the whole OpenAPI document; the generator accepted it, the validator did not. The validator's tests load the real contract. (403701b) A bulk fix must touch only `description` keys that describe a schema, not properties named `description`. (The validator caught a second case before commit.)
- **Do not name a column after a type or keyword (`text`, `type` in some positions).** psqldef's parser rejects `text text`, so `make migration` fails at merge; use `content`. (emergency and directory reviews)
- **Do not declare `CREATE UNLOGGED TABLE` in `db/schema`.** psqldef cannot round-trip it: the generated migration tried a `DROP CONSTRAINT`, which the destructive gate refuses. Use a regular table, and if logging ever costs too much, switch it with a reviewed hand-written `ALTER TABLE ... SET UNLOGGED`. Remember that an unlogged table is empty after a crash or a failover, so it can hold nothing that protects against replay or cost. (rate limit store)
- **Scope each sqlc block to its own schema file.** A block reading the whole `db/schema` directory copies other contexts' models into its package. (dc3bffd)
- **A middleware that reads the body must hand it on; test that the handler receives it unchanged.** (0cf0879)
- **A new Go tool goes into a module where it moves nothing.** `go get -tool` resolves one dependency graph per module: adding oasdiff to `tools/go.mod` upgraded kin-openapi (oapi-codegen's parser) and `x/tools` (golangci-lint's analyzers), which would have changed generated code and lint results in a CI-only change. CI-only tools live in `tools/ci/go.mod`; check `git diff tools/go.mod` for upgraded lines before adding to it. (w36 CI stages)

## Clients

- **Take Expo SDK versions from `npx expo install`, not from an older `expo` patch.** The compatibility list bundled with an early patch can point at release candidates (SDK 58.0.9 listed `react-native` 0.88.0-rc.4), and mixing it with current modules fails to resolve. Install the SDK's current set with `expo install`, then pin each version exactly. (apps foundation)
- **Testing Library for React Native 14 renders asynchronously.** `render`, `fireEvent.*` and `rerender` return promises; without `await` every query fails with "render function has not been called". (apps foundation)
- **Reanimated 4 needs its Jest resolver.** Without `resolver: 'react-native-reanimated/jest/resolver'` any test that imports a component using Reanimated fails while loading the native worklets module. (apps foundation)
- **Treat an unknown reduce-motion setting as "reduce".** `AccessibilityInfo.isReduceMotionEnabled()` answers asynchronously; starting with `false` let entering animations play on the first screen before the answer arrived, and an entrance cannot be taken back. `useReduceMotion` reports true until the OS answers. In Jest, restoring spies also resets React Native's `AccessibilityInfo` mocks, so motion tests set its answer in `beforeEach`. (gentle motion)
- **A formatted input never reads its own inserted characters as the user's.** PhoneField took any '+' in the text as typed by the member; with fast typing the native text ("87") arrived before the formatted "+7" rendered, the inserted '+' counted as hers and a leading 8 stayed +8. Track user intent (typed '+' first in an empty field) in the component, not from the text. (sign-in on a device)
- **On Android, set a controlled `selection` one frame after the value it belongs to.** Given in the same render as a longer formatted text, it is applied to the old text, so the caret lands early and the next digit goes before the last one ("+7 (7" + 0 -> "+7 (07"). Unit tests cannot see it; type key by key on a device (`adb shell input keyevent`). (PhoneField)
- **Teach `tailwind-merge` every custom class group.** It took our type-ramp sizes (`text-body`, `text-title`, `text-display`) for text colours and dropped them next to `text-foreground`, so every Text rendered at the default size and the whole app looked like one small font. `cn()` extends its `font-size` group from `tokens.fontSize`; a new custom scale (sizes, radii, shadows) needs the same. (warm redesign)
- **A served build lives outside the repository tree.** `npm run check` exports `apps/mobile/dist` for localhost, and tree syncs to the stack host delete untracked files: serving `dist`, then `dist-stack`, took the public demo down twice (`ERR_CONNECTION_REFUSED`, then 404). The stack exports to `BIRGE_WEB_DIR` (default `~/.local/share/birge-web`). (web demo)
- **Forms use KeyboardAwareScrollView (react-native-keyboard-controller), not KeyboardAvoidingView.** With edge-to-edge (Expo SDK 58) Android no longer resizes the window for the keyboard (`adjustResize` is ignored), and neither `behavior="height"` nor scrolling on `keyboardDidShow` moved the sign-in fields out from under it on a Nokia 7.2. Verify keyboards on a device, never only in Jest. (sign-in)
- **The member's language choice is local and wins.** The profile used to apply the server's `lang` (default `kk`) on load and switched the app's language by itself after the first sign-in. The choice is saved on the device, offered before sign-in, and sent to the server after sign-in, never pulled back. (lib/language)
- **Entrance motion uses shared values, not Reanimated `entering`.** On the web a layout animation takes the view out of the flow while it runs; the content after an animated Card was drawn over it (the language picker on top of the name card, list rows on top of each other). Opacity and a transform from `useSharedValue` never change layout. Check motion on the web as well as a device. (Appear)
- **Export with `--clear` when `EXPO_PUBLIC_*` change.** Metro caches transformed modules with the inlined public env values, so a second `expo export` with a new API URL still shipped the old one (`localhost` in the bundle). `up.sh web` exports with `--clear`; release builds clear the Metro cache too. (dev stack behind a tunnel)
- **Go targets never use a bare `./...`.** npm packages can ship Go sources (for example `flatted`), and `./...` under the module root then vets, tests and lints them as our code. The Makefile builds the package list once (`GO_PKGS`, `go list` without `node_modules`); new Go targets use it.

- **A normalisation that helps one language must not hide another.** The crisis lexicon read all-look-alike Latin words as Cyrillic in a message with Cyrillic, which turned the English "to" into "то" and missed "I want to die, шаршадым". Detect now checks both readings and matches on either; the crisis path only ever gains matches. Found by the mixed-language eval cases (cmd/birge-eval).

## Process

- **Merge only on the check's exit code.** A pipeline that filters output with `grep` hides a failing test; read `$?` of `make go-check` before merging. (403701b fixed what this let through.)
- **Task branches never contain migrations.** Agents edit their schema file; the tech lead generates the migration on the rebased branch, runs `make go-check` there and only then fast-forwards `main`, so `main` never holds a schema without its migration. (dc3bffd review; 94c04d3 fixed a merge that went first.)
